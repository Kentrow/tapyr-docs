# AGENTS.md

Instructions for anyone, human or agent, changing this repository.

## What this repository is

The engine of **docs.tapyr.eu**: Zensical configuration, theme, home page, build, versioning and deployment. The content is not here. It lives in [Kentrow/tapyr](https://github.com/Kentrow/tapyr) (`docs/`, `examples/`, `providers/`), frozen by each release tag. The contract between the two repositories is [ADR 0010](https://github.com/Kentrow/tapyr/blob/main/docs/adr/0010-documentation-site.md) of Tapyr.

## Rule 1: never edit the exported content

The pages come from `go run ./internal/tools/docsite export` run in a checkout of Kentrow/tapyr. **Never patch them here**, not even a typo:

- a typo, a broken link, a page to rewrite: open a pull request on **Kentrow/tapyr**;
- a page to add, remove or move: change `docs/site.yml` in Kentrow/tapyr;
- a link or anchor that breaks the build: report it on Kentrow/tapyr, its `docsite check` should have caught it.

What belongs here: `mkdocs.yml`, `theme/`, `home/index.md` (the home page; the Tapyr manifest refuses any page at the site root), `tools/`, the workflows.

## The contract

- Export: `go run ./internal/tools/docsite export -ref <ref> -out <empty dir> -index <file.json>` from the root of a Tapyr checkout, with the Go version of its `go.mod`.
- Pages land at their site path (`docs/` dropped, a `README.md` becomes the `index.md` of its directory). Links are already rewritten; images are copied.
- The index gives the navigation (`nav`, mkdocs.yml format) and, per page, its source file. "Edit this page" links go to `https://github.com/Kentrow/tapyr/edit/main/<source>`, always `main`, never the tag (`theme/overrides/partials/actions.html`, keyed by page URL).
- Anchors are GitHub's: keep the `toc` slug configuration of `mkdocs.yml` (`pymdownx.slugs.slugify`, `case: lower`).
- A change of the export format is a coordinated change of both repositories.

## Versions

| URL | Built from |
|---|---|
| `/0.1/`, `/0.2/`… | the latest stable tag of that minor (`v0.1.1`, then `v0.1.2`…); v0.1.1 is the first tag with a manifest |
| `/latest/` | alias of the latest stable minor |
| `/dev/` | `main`, with a "development version" banner |
| `/` | redirects to `/latest/`, or to `/dev/` while no version is published |

Release candidates are never published. Older minors stay online with the outdated banner; the selector lists the last three minors and `dev`. `tools/site_tool.py plan` decides all this from the tags of Tapyr and the `versions.json` of the `gh-pages` branch, where each version keeps its source ref in the `source` property and the engine commit that built it in `engine` (a change to `mkdocs.yml`, `home/`, `theme/`, `tools/site_tool.py` or `requirements.txt` rebuilds every version); `publish` carries it out with [the mike fork for Zensical](https://github.com/squidfunk/mike).

## Standards (same as Kentrow/tapyr)

- English only.
- Workflow actions pinned by commit SHA with the version in a comment; `permissions` minimal per job; no secret (Kentrow/tapyr is public).
- Zensical is 0.0.x: every Python dependency is pinned in `requirements.txt`; updates are deliberate (Dependabot pull requests, then check the build).
- Conventional Commits. No AI co-author trailer, no "generated by" line. `scripts/check-commits.sh origin/main..HEAD` checks both, as the CI does.
- Before a pull request: `python -m unittest discover -s tools`, then the CI build (`prepare`, `zensical build --strict`, `check-links`) must pass with no warning.
- The build must stay without warnings, and every internal link of the HTML must reach a page and an `id` (`tools/site_tool.py check-links`).
